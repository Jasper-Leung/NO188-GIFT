## 0. 一句话结论

**两个项目互补性极高，融合成本低：《归途》有脊骨没有身体，188 号礼物有身体没有脊骨。**
整盘搬进 Godot 等于重做一份已完成的单文件 HTML（重复劳动且高风险）；
只搬脊柱（主角 + 反派 + 期限 + 终局抉择）再加一层薄经济（旅币 + 三铺 + 可购买的明信片），
1–2 天即可让"不只是收集合成明信片"成立。

**黑客松只做 P0 就够上台。**

这一版的关键改动是：**明信片从"免费产出的奖杯"变成"要花钱买纸墨、要自己挣碎片、要亲手写背面"的礼物。**
一句话——**你付得起一张最好的纸，但你付不起一片云。**

## 1. 与 Tripothon S1 主题的对齐

Tripothon S1 的主题是 **"world building"** 的 AI 黑客松，命题 **`A Gift for ______`**，
本作的命题号是 **`A Gift for No.188`**，tagline 是 **"Pack the landscape into your bag."**
（`README.en.md` §9–10、§151）

原方案在主题上是稳的，但"收集 → 合成"这条链太被动，**礼物是游戏发给你的，不是玩家做出来的**。
加了经济层之后，命题反而更硬了：

| Tripothon S1 要求 | 整合后的落点 |
|---|---|
| **A Gift for No.188**（礼物必须是主角，不是道具） | 明信片现在由三层拼成：**买来的纸墨**（经济）+ **挣来的五块碎片**（骑行）+ **选出来的背面**（抉择）。三层缺一层就不是 No.188。 |
| **Pack the landscape into your bag**（把风景装进包里） | 经济系统字面化这句话：旅币是骑出来的，纸墨是买回来的，风景是花旅币**装进纸里**的。风景从"被看"变成"被携带"。 |
| **world building**（世界观密度） | 价格是密度最高的一种世界观陈述。三铺九件商品 + 一栏"无价"，等于在说"这个世界有生活在里面"。 |
| **AI 3D 素材展示**（Tripo 是本赛的主工具） | 商品天然是 Tripo 提示词的最佳载体。`docs/station_marker_prompts.md` 现有 12 条驿站提示词，加上纸/墨/蜡封/灯笼/信封/香囊约 6–8 件商品，**世界资产从 12 件扩到 ~20 件，且每一件都能在界面上被玩家摸到**（驿站模型是骑过去的，商品是点开的）。 |

**一个顺带的好处**：三铺的摆放位置本身就是世界叙事——驿铺在起点、茶铺在半山临水处、灯铺要骑过半个环线才见得到。
商店不是 UI 面板，是**路径上的地理事实**。

## 2. 与 `README.en.md` 现有口径的冲突（必须先说清）

`README.en.md` 第 23–32 行现在写着：

> **No plot, no dialogue, no branching.** The narrative is thematic, not dramatic.
> **No combat, no timer, no difficulty curve.** Deliberately gentle.
> One run is 5–8 minutes, with **no failure state**.

本文（含上一版加入的主角、反派、期限、分结局）与本次加入的经济层，**逐条与这段话相反**。
这不是疏漏，是有意转向；但转向必须被记录下来，否则下一位维护者会把它当回归事故修掉。

### 2.1 逐条处置

| README 现有口径 | 本文处置 |
|---|---|
| No plot / no dialogue | **作废。** 序章 3 屏 + 郑铎 3 场 + 结局独白（§7.1 / §7.2 / §7.3）。 |
| No branching | **作废。** 二选一 + 三个结局（§7.3）。 |
| No timer | **作废，但换轴。** 不做天数倒计时，改用**里程触发**（§7.2），因为 `progress_km` 是已有的进度轴，零新管线。 |
| No difficulty curve | **保留（精神）。** 经济层不设失败门槛：素笺套餐 0 旅币，永远买得起（§6.2）。 |
| 5–8 分钟一局 | **部分保留。** 序章 + 郑铎 + 结局加起来约 +2 分钟；经济层不增加时长，只改终点前那一下的重量。 |
| **no failure state** | **必须保留，且是硬约束。** 见 §2.2。 |

### 2.2 `no failure state` 是本方案的一条红线

**经济系统最大的风险就是把它做成失败条件。** 一旦"买不起明信片"，
玩家就会卡在一个没有产出的终点上——那正是《归途》冻结版 §7 明确否决过的死锁的翻版。

本方案的处置（**不可改动**）：

- **素笺套餐定价 0 旅币**，任何旅币余额都能买到一张空白明信片。
  经济层升级的是**礼物的体面**，永远不升级**礼物的存在**。
  买不到的从来不是礼物本身，是礼物的体面。
- **不许出现"钱不够就走不到终点"的路径。** 里程是自动累积的，
  骑完全程就一定有钱；钱只决定明信片好看还是朴素。
- `verify_economy.gd` 要把这条写死（§12.1）。

### 2.3 README 需要跟着改

如果本方案被采纳，`README.en.md` 至少需要动三处（**本次不改，仅登记**）：

1. §22–32 "What kind of game is this?" — 从"No plot / No branching / no timer"改为
   "a short journey with a story spine and a gift economy"，并把 `no failure state` 保留下来。
2. §36–44 "188 is three things at once" — 加第四层：**188 km = 骑出的里程 = 铸出的旅币 = 礼物编号**。
3. §68 之后 "Play" — 补商店与旅币的说明。

不改 README 就上台，等于让评委拿一份说"没有剧情"的稿子去评审一个有剧情的游戏。

## 4. 黑客松判定：够不够

一个评委能在 2 分钟看懂、10 分钟内感到分量的最小玩法，需要 5 条：

| # | 条件 | 整合前 | 整合后 |
|---|---|---|---|
| 1 | **前提**（玩家为什么在这里） | ❌ | ✅ 失业 + 母亲失踪 + 期限（序章 3 屏） |
| 2 | **循环动词**（可重复的核心动作） | ✅ 骑 → 打卡 → 小游戏 → 碎片 | ✅ 不变，**并产出旅币** |
| 3 | **反作用力**（有东西在推你、向你收费） | ❌ | ✅ 郑铎 3 场 + **旅币的取舍**（灯笼还是明信片） |
| 4 | **终局抉择**（结局由选择决定） | ❌ | ✅ 二选一 + 三个结局 |
| 5 | **可复述的钩子**（一句话讲得清） | ⚠️ "东坡赏心乐事"是氛围，不是钩子 | ✅ **"你付得起一张最好的纸，但你付不起一片云"** |

**判定：整合前 2/5，整合后 5/5。**

不做的事（明确否决，与上一版一致）：

- ❌ 在 Godot 里重做《归途》上篇 HTML 版（那份已有 99 项回归全绿，重做是浪费）
- ❌ 战斗系统（与"守驿人记路，不记己"的价值观冲突，《归途》续作大纲 §7 明确否决）
- ❌ 恋爱线（稀释主题）
- ❌ 改路线几何（8 字形是整套流式与交叉点验证的地基，见 §5.2）
- ❌ **经营模拟**（《归途》的温泉/木柴/作物/客房是 30 天经营盘，本方案只做"薄经济"，见 §6.1）
- ❌ **把明信片设为不可替代的付费墙**（违反 `no failure state`，见 §2.2）

## 5. 三个决定性的嫁接

这三条决定了融合成不成。第一条最重要。

### 5.1 云茶琴竹禽 ≠ 纪念品，而是五种「守驿」

《归途》的调性是寻母、失踪、封印；188 的调性是东坡的闲适诗意。**硬混会打架，
观众会觉得是两个游戏缝在一起。** 桥就在这里：东坡这五件乐事，正是**守驿人安慰迷路人用的语言**。

| 碎片 | 现有驿站与文案 | 重解为守驿人的哪种「记路」 |
|---|---|---|
| 云 | 云影台（idx 7）「雨后台阶看云」/「像一封没有署名的信」 | **望归** —— 云影就是那张寄不出的信 |
| 茶 | 茶烟小筑（idx 10）「朋友来了先煮茶」 | **待客** —— 守驿人先把人留住 |
| 琴 | 琴音林（idx 13）「把风声听成琴音」 | **听路** —— 风声是路的自述 |
| 竹 | 竹雨庭（idx 14）「夜雨敲竹」/「把一盏灯守到天明」 | **守夜** —— 字面意义地守 |
| 禽 | 花房·禽语湖湾（idx 4）「一只鸟替湖回答」 | **引路** —— 替沉默者答话 |

这样东坡的温度完整保留，故事也装得下。

### 5.2 8 字形不是几何偶然，它就是设定

《归途》最漂亮的一句是：**「第十八驿不是终点，而是入口。」**

本作的路是 lemniscate 8 字、两环在中间打结——这不就是"一条返回自己入口的路"吗？所以：

- **交叉点**（`tools/verify_crossing.gd` 已经在测的那处特殊几何位置）= **第十七驿**，
  雾隐林深处那个松动的入口
- **两环收拢处** = **K188 终点观景台**，观者看到的正是"终点其实是入口"
- 「迷路者为什么会在 188km 的直路上走失」有了答案：**因为这条路的形状本来就是个结**

现有代码一行不用改，几何被叙事化。

### 5.3 明信片只是礼物的一半 —— 而且纸要花钱

**188号礼物 = 母亲留给第十八代守驿人的第 188 号礼物。**

> ⚠️ 本节原文写的是「188km = 路的长度」。这句已经不成立：世界的环路只有 1228.8m，
> 188 是**编号**不是里程。顶栏、所有文案和所有解锁门都已在 2026-09-30 改成驿数口径，
> 见 scripts/HUD3D.gd 顶注释。里程只在内部作旅币经济口径（`GameManager.progress_km`）。

明信片现在有三层，**只有第一层是买的**：

| 层 | 由什么决定 | 可否用旅币购买 |
|---|---|---|
| **纸面**（材质 / 纸纹 / 墨色 / 蜡封 / 信封） | 商店买的套餐与散件 | ✅ **可以**，且是三档明码标价 |
| **正面**（五块碎片的印样） | 五个驿站的小游戏 | ❌ **不可以**。商店里明列"无价" |
| **背面**（一句话） | 终局二选一 | ❌ **不可以**。只能写，不能买 |

> 收集只是凑齐了纸面，你选什么才写了背面，而**纸要花钱**。
> 这一条把"收集合成"扭成"取舍 + 抉择"：钱决定礼物的体面，行动决定礼物的内容，选择决定礼物的意义。

## 6. 经济系统与商店

### 6.1 设计立场：薄经济，不做经营

《归途》的经济是**经营盘**：30 天、温泉等级、木柴消耗、客房随机入住、作物生长周期，
靠 `经济波动自检.js` 跑 24 次统计区间才敢交付。那套东西的复杂度是本项目体量的 5 倍以上，
而且它的张力来自"会不会被征收"——而本项目刚刚在 §2.2 里承诺了 `no failure state`。

**所以本方案只取《归途》经济里的一条脊椎：有货币、有价格、有取舍；不取它的整个内脏。**

判定标准：**旅币的收支只沿已有的进度轴发生，不新增任何计时器、任何 tick、任何随机性。**

### 6.2 货币：旅币（`Lvbì`）

沿用《归途》冻结版 §6 的货币名。之所以不另起一个名字，是为了保留"旅"这个字的旅行义
（本作是骑行旅行），也让两套设定的经济可以互相引用。

**产出（全部挂在已有轴上）**

| 来源 | 单次 | 上限 | 说明 |
|---|---|---|---|
| 里程 | +2 / 公里 | 376 | `progress_km` 已是累加量；按整数公里发放 |
| 首次路过任意驿站 | +3 | 48（16 站） | 让 §7.4 那 16 站余响都有经济意义，不再是纯文本 |
| 碎片驿站首次打卡 | +15 | 75（5 站） | 挂 `GameManager.check_in()` |
| 碎片驿站重复打卡 | +5 / 次 | 每站 +10（`MAX_VISITS_PER_STATION=3`） | 同上一函数 |
| 小游戏成功 | +20 | 100 | 挂 `_on_mini_game_done(SUCCESS)` |
| 小游戏失败 | +5 | — | 安慰奖，**不惩罚**（守 §2.2） |
| 首次拾取碎片 | +30 | 150 | 挂 `fragment_collected` 信号 |

**消耗（三铺九件，见附录 C）**

| 档 | 内容 | 价 |
|---|---|---|
| 素笺套餐 | 空白明信片（纸纹最简） | **0** |
| 上笺套餐 | 纸纹 + 淡墨 | 180 |
| 珍藏套餐 | 金描边 + 蜡封位 + 印章；**需 5/5 碎片** | 460 |

散件：宣纸 60 / 松烟墨 50 / 信封 40 / 蜡封 45 / 灯笼 90（最多 2 件）/ 香囊 55。

**理想全清总额 = 799 旅币**（376 里程 + 48 路过 + 75 首次打卡 + 50 重复打卡 + 100 小游戏 + 150 碎片）。
这个数字是**算出来的，不是拍的**，`verify_economy.gd` 会按公式重算一遍（§12.1）。

**关键的取舍（这才是经济系统存在的理由）**：

- 合理全购合计 **890**（珍藏 460 + 宣纸 60 + 松烟墨 50 + 信封 40 + 蜡封 45 + 灯笼×2 180 + 香囊 55），
  比 799 高出 **91**——差不多正好一盏灯笼。**必须做减法，而且减法有得选**。
- 最终只剩三种收法：
  - **两盏灯笼、不升纸墨**（780）——视野最远，纸面最素
  - **一盏灯笼 + 宣纸**（750）——视野还行，纸面讲究
  - **一盏灯笼 + 松烟墨**（740）——视野还行，墨色讲究

  三者的共同点是：**更远的视野 vs 更讲究的纸，二选一**。这就是 §8 那句
  "你听见过去越多，眼前的世界越看不见"的账单。
- 珍藏套餐额外要求 5/5 碎片——**这不是新的失败门槛**：碎片本就是现有核心循环，
  且素笺/上笺不需要碎片，明信片永远买得到。

### 6.3 三铺：商店是路径上的地理事实

不做一个"打开背包就能逛"的抽象商店。三铺各占一座**非碎片驿站**，骑过去才买得到。
这是 Tripothon S1 的 "world building" 最实在的一条——**商品有地址**。

| 铺 | 所在驿站 | 开档 | 卖什么 | 为什么放这儿 |
|---|---|---|---|---|
| **驿铺** | 起程驿楼（idx 0） | 开局即开 | 三个套餐 + 宣纸 / 松烟墨 / 信封 | 起点就是邮局；**核心目标永远可达成**，不许把明信片锁在进度后面 |
| **茶铺** | 南溪茶寮（idx 2） | 开局即开 | 香囊 | 东坡"客至汲泉烹茶"，香囊是待客之物 |
| **灯铺** | 灯影亭（idx 8） | **K60 解锁** | 蜡封 / 灯笼 | 骑过半个环线才见得到，构成一个中段目标；"过灯"本就与夜、与守有关 |

三铺共用**一个** `ShopPanel.gd`，商品数据外置到 `scripts/shop_data.gd`（照 `road_data.gd` 的写法），
不在面板里硬编码。这样加商品是纯数据工作。

### 6.4 「无价」栏：这套设计最值钱的一屏

驿铺的商品列表里，**固定留出一栏**，列出：

```
云  茶  琴  竹  禽
      —— 无价，路上自取
```

价格栏一律显示 `无价`，不可点击购买。

这一栏是 §5.1 那句"云茶琴竹禽 = 五种守驿"的**可视证据**，也是本方案那句钩子的来源：
你可以在店里把纸、墨、蜡封、灯笼、信封一样一样买齐，唯独买不到你在云影台看过的那片云。

演示时把光标停在这一栏上就够了。它比任何旁白都清楚。

### 6.5 存档与版本

`GameManager.SAVE_VERSION` 从 2 → 3，新增字段：

- `lvbi: int`（当前旅币余额）
- `inv: Dictionary`（已购商品 id → 1）
- `spent_km: float`（已计费的里程，防止重复发钱）

沿用现有 `_save_game()` / `_load_save()` 的写法（`ConfigFile` + 版本不匹配即丢弃）。
`reset()` 里补上 `lvbi` / `inv` / `spent_km` 的清零。

## 8. 代价机制：心神 → 视野（与经济联动）

《归途》的 `mood` 原设定是抽象数字（1~5，≤2 收入打折 ×0.9 / ×0.8，休息 +1，下限 1 永不归零）。
**本作没有收入系统，硬做没意义。** 翻译成一件事：

> 每拾取一块碎片（= 一次深度余响），心神 −1；心神越低，**草皮与树的加载半径越收**。

**「守驿人记路，不记己」变成字面意义：你听见过去越多，眼前的世界越看不见。**

**数值表（新增，本文自定，不来自冻结版）**

| 心神 | 5 | 4 | 3 | 2 | 1 |
|---|---|---|---|---|---|
| 半径系数 | 1.00 | 0.90 | 0.80 | 0.72 | **0.65** |

初始心神 4（沿用冻结版 §7），拾取 5 块碎片后落到 1，系数 0.65——**不低于 §5 原红线 0.6**。

**与经济的联动（本次新增，是本方案最有意思的一处）**：

- **灯笼（90 旅币，灯铺）：半径系数 +25%**，可叠两件，**上限 +50%**
- 心神 1 + 两件灯笼 = 0.65 × 1.50 = **0.975**，几乎抵消全部惩罚

这意味着：心神惩罚**可以被花钱买回来**。而这正是取舍所在——
那 180 旅币本来可以让明信片好看一大截。**你听见过去越多，眼前的世界越看不见；
要不要花钱让眼睛重新看见，是你自己的事。**

**「守驿人记路，不记己」于是有了两种读法**：
母亲是没钱买灯笼的人（她是守驿人，不是消费者）；你是可以买得起、却犹豫要不要的人。

**实现几乎免费**：`GrassScatter` 与 `TreeScatter` 的加载半径本来就是参数
（`GrassScatter.RADIUS_DESKTOP`、`TreeScatter.RADIUS_DESKTOP` / `RADIUS_MOBILE`），
接一个 `心神 × 灯笼` 的合成系数即可，且天然被 `verify_grass_scatter.gd` / `verify_tree_scatter.gd` 拦回归。

**设计红线（照抄冻结版 §7「为什么不把它做成失败条件」）**：

- **只衰减视野，不锁任何操作**。下限保护必须有——《归途》初版曾计划"mood ≤ 1 无法探索"，
  因它会让刚拿完碎片的玩家被锁在原地、重演通关死锁，已被否决
- **不许用经济手段制造失败**：买不起灯笼不会卡关，只会让世界看起来更空（§2.2）
- 系数最低档不要低于 0.6，否则演示时画面会显得像 bug

**香囊（55 旅币，茶铺）**：心神 −1 的**视野惩罚减半**，永久生效一次。
它是灯笼的替代方案——一次性对冲 vs 持续加成，**同样是 70 量级的钱，两种买法**。

**演示价值**：心神一掉，远处的树排和草皮圈肉眼可见地收缩；买一盏灯笼，它们又长回来。
这是评委能看见的机制，不是数字。

## 9. 巡路日志（P1）

《归途》续作大纲把「巡路日志」列为最强反"收集向"装置。本作的落法：

- `PausePanel` 加一个「巡路日志」Tab
- 每次打卡追加一条，**用母亲的声音写**（不是系统播报）
- 心神掉到某档时，**早期的条目变成空白页**——你忘了自己做过什么
- 终局时全屏展示，日志本身就是结局的一部分

**与经济联动（本次新增）**：日志里**记一笔账**——每一笔旅币的进出都写一行。
终局那屏同时是"你这趟骑了多远、花了多少、买了什么、最后选了什么"的总结。
这比任何结算面板都更像"礼物"。

## 12. 验证与防漂移

### 12.1 直接抄《归途》踩过的一条坑

它文档里记着一个**真实缺陷**：旧版规则"碎片 ≥ 9 才解锁终点"，而全局只有 4 枚主线碎片，
且碎片 4 本身就在终点剧情里 → **循环依赖，结局永远不可达**。这是纯设计错误，
跑测试跑不出来，最后靠人工发现并作废。

所以 `verify_story.gd` 的第一条断言必须是**解锁链可达性**：
对每个解锁阈值，断言存在一条不依赖自身的前置路径。

**经济层有一个一模一样的死锁形态**：**一个买不起的价格，就等于一个不可达的结局。**
所以 `verify_economy.gd` 的第一条断言必须是**可负担性可达性**：

- 按 §6.2 的公式**重算**（不是照抄常量）理想全清总额，断言 ≥ 珍藏套餐价 460
- 断言：只骑完全程、什么都不做（376 + 48 = 424）仍 ≥ 上笺套餐价 180
- 断言：开局旅币余额 0 时，素笺套餐（0 旅币）仍可购买 ← **这就是 `no failure state` 的机器证明**
- 断言：合理全购合计 > 全清总额，差值 ≥ 一件灯笼价 90 ← **取舍真实存在的机器证明**

### 12.2 再抄它后来自己加的硬规则

> 所有"玩家能看到的状态"必须有至少一条断言，且**断言读的是渲染后的显示文本，不是内部变量**。

《归途》原话是"读渲染后的 DOM 文本"；本作对应的是断言 `HUD3D` 的 `Label.text`
而不是 `GameManager.progress_km` / `lvbi`。理由一致：内部状态对了、显示错了，玩家看到的是错的。

经济层要额外断言的具体文本：

- `HUD3D` 旅币 `Label.text` 在每次 `earn()` / `spend()` 后等于预期值
- 三铺面板的价格 `Label.text` 与 `shop_data.gd` 逐项一致
- **「无价」栏五个名字都在渲染后的文本里，且对应的购买按钮 `disabled == true`**
  （这条是 §6.4 那句钩子的回归保护——不能让人把云改贱了）
- 未竟结局的明信片**确实导出了一张 PNG**（正面缺格、背面空白，但文件存在）

### 12.3 P0 / P0.5 交付前必跑

```bash

"$GODOT" --headless --path . --script tools/verify_story.gd          # 新增：解锁链可达性
"$GODOT" --headless --path . --script tools/verify_economy.gd        # 新增：可负担性 + no-failure
"$GODOT" --path . --script tools/lookdev_grass.gd                    # 若动了心神/灯笼半径系数
```

## 13. 风险

| 风险 | 表现 | 对策 |
|---|---|---|
| **调性混战（最大）** | 《归途》寻母失踪 vs 188 东坡闲适，观众觉得是两个游戏硬缝 | 必须做 §5.1 那一步重解（云茶琴竹禽 = 五种守驿），不做就别融合 |
| **经济把它做坏了** | 加了货币和商店，玩家记住的是"一个换钱的骑行小游戏"，诗意被稀释 | §6.1 只做薄经济；**「无价」栏是防稀释的保险栓**——玩家第一眼看见的是"买不到云"，不是"我有 799 旅币" |
| **经济变失败条件** | 玩家买不起明信片，卡在没有产出的终点 | §2.2 红线：素笺套餐 0 旅币；`verify_economy.gd` 机器证明 |
| **几何被改坏** | 有人为了"更像一条公路"去改 8 字形状 | 用 §5.2 让 8 字成为设定，成本为零；`road_data.gd` 的形状不动 |
| **重演《归途》的死锁** | 解锁阈值写成自引用，结局不可达；或价格写成买不起 | 见 §12.1：`verify_story.gd` + `verify_economy.gd` 先写，再动剧情与定价 |
| **心神做成失败条件** | 玩家拿完碎片被锁在原地 | 见 §8 红线：只衰减视野，不锁操作 |
| **README 与实现分裂** | 评委拿"No plot, no branching"的稿子看一个有剧情的游戏 | §2.3：采纳本方案必须同步改 README，否则别上台 |
| **P2 失控** | 经营盘一开就散架 | P2 明确不进黑客松；每个里程碑结束都要能独立跑通一次完整流程 |

**预算校验（`verify_economy.gd` 要按公式重算，不要照抄这几个数）**

| 场景 | 收入 | 结论 |
|---|---|---|
| 开局 | 0 | 素笺 0 旅币 → **明信片永远拿得到**（`no failure state` 的机器证明） |
| 只骑完全程，什么都不做 | 376 + 48 = **424** | 买得上笺 180；**买不了珍藏 460** → 珍藏确实奖励了"真的在玩" |
| 全清（全里程 + 16 站路过 + 5 站打卡 ×3 + 5 小游戏 + 5 碎片） | **799** | 合理全购 **890** > 799，差 **91** ≈ 一盏灯笼 → **必须做减法** |
| 收法 A：珍藏 + 灯笼×2 + 信封 + 蜡封 + 香囊 | 460+180+40+45+55 = **780** | 剩 19，纸墨不升级 → 视野最远，纸面最素 |
| 收法 B：珍藏 + 灯笼×1 + 宣纸 + 信封 + 蜡封 + 香囊 | 460+90+60+40+45+55 = **750** | 剩 49 → 视野还行，纸面讲究 |
| 收法 C：珍藏 + 灯笼×1 + 松烟墨 + 信封 + 蜡封 + 香囊 | 460+90+50+40+45+55 = **740** | 剩 59 → 视野还行，墨色讲究 |

**三种收法都能达到珍藏笺**（都有 5/5 碎片的前提下），差别只在"视野还是纸"。
这就是 §6.2 说的那个二选一，不是算术题。
