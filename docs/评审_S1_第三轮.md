## 2. 完全不了解本作的玩家：我走了一遍

以下按真实时间顺序写，**不写设计上应该怎样，只写我实际看到什么**。

**0–4 秒**：标题页。深底、8 字环线做背景纹样、礼物盒、一行「沿着 188 号环线，重演五件小事」。
读得懂。点「开启旅程」。

**5–10 秒**：操作说明面板。上面先列了「旅币 / 心神 / 驿 / 碎片」四个词，下面才是按键。
**这一手很好**——先给名词再给操作，我立刻知道这游戏在管什么。

**10 秒起**：第一次踩上踏板。前三秒我以为我在骑过一片**麦田**。

这就是那一堵草。它从路肩一直长到超过车把，8 米以外就变成一堵不透明的墙，
把地形起伏、远处山脊、站点的地基全遮住了。我看不见"路在往哪儿爬"，
也读不出"这是一片开阔地"还是"我正穿行在某个高人的玉米地里"。
（`s19_day` / `s07_villain` / `s10_revisit` / `lookdev_grass/04m.png` 四张图都能复现。）

**第一次到站**：脚下亮圈 + 「空格 · 在此完成乐事」。清楚。靠过去有轻微的边界推力，会被推开，
这个手感是对的——它告诉你"站是要拐下路的"。

**第一个小游戏（茶）**：标题「按住注水，3秒后完成」，下面一条进度条，右边写「还差 3.0 秒」，
**条上有一道跨在条外的刻痕**。这个设计我很喜欢——门槛画在条上而不是只写在字里。
但壶是**一个纯黑的剪影**，我注水的时候看不到水位在涨，壶本身给不了一点反馈，
我只能盯着下面那条条。

**回访**：顶栏写「再访 花房·禽语湖湾 ↑ · 还差 2 次」，脚下圈也写「空格 · 再办一次 · 还差 2」。
**同一个数字出现在三个地方**——这让我非常相信这个游戏是诚实的。

**路过普通驿站**：耳边浮一句风景话。这个我喜欢，是"你真的在经过什么地方"的证据。

**集齐那一刻**：面板弹出来，「收下明信片 · 结束这一趟」/「再骑一圈 · 刷到完满」。
**这是我这一趟最松了一口气的地方**——因为在此之前我完全不知道这游戏怎么结束，
按原来的路径我要骑 25 分钟才可能碰到出口，而现在它在信息量最大的那一秒就给了出口。

**明信片**：路线图上 16 个点、五件乐事各 3 次、五张碎片色卡、蜡封「完」。
这是整个作品的目的地，而它真的到了。

## 3. 问题清单

### P0 — 挡在"能给人看"前面的

#### P0-1　草皮齐腰成墙，把地形、尺度和风景从画面里删掉了

**证据**（四张互证）：
- `lookdev_grass/04m.png`：相机 `EYE_H = 1.6m`（与玩家眼高一致），4m 处的草尖落在
  屏幕 y≈430。按 65° 竖直 FOV 反解：草尖高度 ≈ `1.6 - 4·tan(14.4°)` ≈ **0.57m**。
- `s19_day` / `s10_revisit`：拿同框的车（实高 **1.37m**）当尺子，草没过车把，**约 0.8–1.0m**。
- `s07_villain`：8m 以外整片变成不透明绿墙，站牌只剩露出来的顶。
- `s21_collect`：地形起伏完全不可见，看不出哪是丘哪是谷。

**为什么回归没抓到**（这是本条最要紧的一半）：
`verify_grass_scatter.gd:687` 断言的是着色器源码里的 `card_height <= 0.10`（当前 0.085），
`_check(h > 0.0 …)` 也只是读文本。**但渲染出来的高度是**
`card_height × RING_SCALE[r] × scl × mix(0.75,1.25)`，
`RING_SCALE = [1.0, 1.0, 1.8, 3.2]`（`GrassScatter.gd:59`）、`scl ∈ [0.72,1.35]`（`:694`），
**最坏 = 0.085 × 3.2 × 1.35 × 1.25 ≈ 0.46m**，近景那一圈还要再乘上密度的堆积。
`verify_grass_scatter.gd:297` 只验了 `smax < 0.72 × RING_SCALE[r]`——**验的是倍率本身，不是倍之后的尺寸**。
所以：源码是绿的，回归是绿的，画面是一地麦子。**这正是 CLAUDE.md 自己写过的那个坑
（"一条回归在绿，可能是因为它自己踩在它要守的那个漏洞上"）的第 N 次复现。**

**修**：
1. `RING_SCALE` 收紧到 `[1.0, 1.0, 1.35, 1.9]`，并把 `card_height` 降到 `0.055`。
   目标：**近景任何距离的草尖不超过 0.25m**，即 1.6m 眼高看得过去。
2. 加一条**量得到结果的**断言：在 `lookdev_grass` 的 4m 图里，取画面下缘往上那一列，
   量"草的墨掩膜上沿"离地平线的像素距离，反解成米，要求 **≤ 0.25m**。
   判据要落在**画出来的那张图**上，不要再读源码文本。
3. 近景（ring 0/1）加一道**贴地淡出**：0–0.12m 的叶片透明度降到 0.35，让草"长在地上"
   而不是"立在路上"。

#### P0-2　黄昏时草皮是全屏最亮的霓虹金，不受光

**证据**：`s21_collect`——天空深红、路面近黑、远山暗粉，唯独两侧草皮是饱和度极高的金黄，
比场上任何东西都亮，像自发光。`s22_synthesis` 同样。

**成因**：`grass.gdshader` 的 `blade_base` / `blade_tip` / `ground_color` 是写死的常量色，
`fragment()` 直接输出，不走引擎的光照；而地形和路面走的是有光照的管线。
DayCycle 改了太阳和天色，改不动这三个常量。

**修**：`fragment()` 的最终色乘一个从场景取到的环境光系数
（`DayCycle` 每帧把 `sun_light.color * sun_light.energy` 写进 uniform），
并让 `blade_tip` 相对 `blade_base` 只做**色相偏移**而不是提亮。
验收：`s21_collect` 里草皮的亮度**不得高于同帧的天空**（量图）。

### P1 — 会被评委当场指出来的

#### P1-1　禽游戏里「乌鸦」在深色卡上看不见

`s_mg_bird`：4 张卡底色都是深藏青（≈ `#2a2f3a`），而乌鸦是**纯黑**。
一个"从四只里认出刚才那一只"的记忆游戏，其中一只的目标对比度接近 1.1:1。
白鹭（米白）、麻雁（橙）、燕子（蓝）都没问题，**只有乌鸦是黑的**——
这显然是个意外，不是设计。

**修**：`BIRD_SHAPES` 里乌鸦改成深炭灰并在卡底加一圈浅色描边，
或者给它一枚可辨识的喙/眼高光。判据：四张卡的**主体与底色** WCAG 对比度都 ≥ 3.0:1，
加进 `verify_mini_game.gd`（现在只验形状两两不同，没验可读性）。

#### P1-2　茶游戏的壶是纯黑剪影，注水时看不到水位

`s13_mg_tea`：壶身填充近纯黑（`#1a1008`）压在深棕底上，只有轮廓是橙线。
玩法是"注水"，**但壶里没有水**。玩家唯一的反馈是下面那条进度条。
另：壶上方三个浮着的灰圆点读起来像随机污点，不像蒸汽。

**修**：壶身改成可填充的内部区域，注水时水位线真的上涨（复用 `MiniGameBar` 同一个比例）；
三颗点改成有 alpha 渐隐的蒸汽。

#### P1-3　README 与代码对不上：顶栏到底带不带分母

## 4. 新手体验里，机制上还没交代清的三件事

这些不是 bug，是**我玩完之后仍然不知道的事**，而它们本该被设计说出来：

1. **心神到底是什么。** 操作说明里它被列为四个名词之一，但整局下来没人告诉我
   它是干什么的。我在 `s21_collect` 看到它从 4 掉到 1，仍然不知道那意味着什么、
   会不会有后果。（设计文档说它是"叙事较重的段落压暗画面"——那么**该在压暗那一刻说一句话**。）
2. **旅币是死的。** 我结束时 721 枚，一次都没花。驿铺在屏幕上，我路过了，没进去，
   也不觉得该进去。**一个数字如果没有可感知的用途，它就不是系统，是装饰。**
