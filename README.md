# 188号礼物

**把这片风景装进背包。**

一款短而平缓的 3D 骑行旅程，围绕苏轼"赏心乐事"展开。
骑一条自行构造的 8 字环线，对五座虚构驿站各拜访三次，
把十五个片刻合成一张可以写字、可以导出的明信片。

为 **Tripothon S1**「世界构建」AI 黑客松而作。主题：
*给 ______ 的礼物。本作是：**给 188 号的礼物**。

> 这是一部虚构叙事 demo。路线是一条纯数学的 8 字图案，不指向、不复现任何现实公路。
> 驿站名与场景布局均为艺术虚构。本作不声称代表任何真实旅游公路、官方驿站品牌或
> 真实景区运营。题材取自公有领域的东坡诗文（1037–1101）。

英文版见 [README.en.md](README.en.md)。

## 这是个什么游戏？

**一段有氛围的旅程，回报在收集与合成之后。**

不是平台跳跃，不是竞速，不是 roguelike。没有战斗，也没有会结束这一趟的失败画面。

- **你骑一条固定环线**，在驿站停下。骑行是连接它们的线，不是挑战本身。
- **有对白。** 每座碎片驿站会在你第一次到访时自我介绍；一个常驻角色（郑铎）会
  在你越骑越远时打断你三次。他的台词讲的是一辈子在丈量这条路、而不是在骑它的人。
- **结尾有一个选择**，而且不是装饰性的——见[最后由你决定的事](#最后由你决定的事)。
- **有五个小游戏**，一件乐事一个。玩砸了就会输；输掉的只是这一趟的奖励，别的什么都不少。
- **有经济。** 骑行与打卡赚旅币，在三间路边的铺子（驿铺、茶铺、灯铺）里花掉。
  一个心神值会在叙事较重的段落压暗画面，骑行时自己慢慢恢复。

最接近的参照是《Journey》那一路的短程朝圣：情绪来自"抵达"，不来自"打赢什么"。

## 「188」是两件事，不是三件

| 「188」指 | 在游戏里 |
| :--- | :--- |
| **188 号** | 礼物的编号，明信片上印着 |
| **16 座驿站** | 沿路经过的"驿"；顶栏写 `已过 n 驿`（不带分母——驿数会变，抄死分母就得回来改文案） |

**它不是里程。** 旧版 README 把这里写成"188 公里环线"，而这个说法玩家十秒内就会
自己拆穿：这条环线实测 **1228.8 m**，按 15 m/s 极速算跑满一圈只要 **82 秒**——
折算到 188 公里是每小时七千多公里。这个数字自始至终是一个编号，
游戏内所有文案现在都这么写（里程只作内部经济单位，从不给玩家看）。

## 三次到访，五件乐事

每座碎片驿站要去 **三次** 才算刷满。第一次到访拿到的就是碎片——
"已经收过"和"不用再去了"是两件事，游戏里处处把它们分开：
顶栏、小地图高亮、脚下的圈，在这座驿站真的刷满之前都会一直指着它。

每一次到访都会玩到五件乐事之一，轮着来：

| | 第 1 次 | 第 2 次 | 第 3 次 |
| :--- | :--- | :--- | :--- |
| 云影台 | 云 描云 | 茶 煮茶 | 琴 复琴音 |
| 茶烟小筑 | 茶 煮茶 | 琴 复琴音 | 竹 砍竹 |
| 琴音林 | 琴 复琴音 | 竹 砍竹 | 禽 认鸟 |
| 竹雨庭 | 竹 砍竹 | 禽 认鸟 | 云 描云 |
| 花房·禽语湖湾 | 禽 认鸟 | 云 描云 | 茶 煮茶 |

**第一次**到访仍然是这座驿站自己的那件（云影台还是描云），
所以第一趟的手感与配对关系一个字没变。15 次打卡里每件乐事正好各出现 3 次，
同一座驿站连着两次到访也绝不会撞上同一件。

驿站对白则**只在第一次到访时**播。那是驿站在介绍自己，
重播只会把三次到访本该积累出来的那种"越走越深"的感觉磨平。

## 五个小游戏

| 乐事 | 玩法 | 失败条件 |
| :--- | :--- | :--- |
| 云 Cloud | 用鼠标（或方向键 + 空格）描出云的轮廓 | 描到 75% 以下就松手 |
| 茶 Tea | 按住把壶注满 3 秒 | 松手清零（这一件不会失败） |
| 琴 Music | 复述一段 4 音的旋律 | 弹错音，或沉默超过 2.5 秒 |
| 竹 Bamboo | 每根竹子冒出来时按一下（共 5 根） | 按早了或按晚了 |
| 禽 Bird | 看一只鸟，再从四只里认出它 | ——（限时，不判对错） |

失败不致命：你会看到一块面板说明结果，骑开之后这座驿站立刻可以再进来。

五个小游戏都能纯键盘玩，`Esc` 随时取消——因为屏幕上的取消按钮是 `_draw()` 画出来的
假按钮，键盘点不到，少了这道口子键盘玩家会被困在那一屏。

## 最后由你决定的事

十五次到访全部走完之后，你可以决定这份礼物怎么收尾：

- **留门 / Leave the Door** —— 明信片背面已经替你写好，蜡封保持完整。
- **放手 / Let Go** —— 背面留白给你自己写，正面上的蜡封被掰开。

这两种差别落在**导出 PNG 的正面**上，不只是菜单里的一行字。
之后你可以在背面自己写字，游戏会实时预览你将要导出的那一张。

明信片按你走到哪一步分四档：**初旅 / 探索者 / 朝圣者 / 大师**。

想早点收工的话，暂停面板里有「结束这一趟 · 收下明信片」——
它要等你至少拿到一块碎片才出现，因为一张空卡没什么可说的。

## 要玩多久

跑完到明信片大约 **20–30 分钟**。这个数字是按真实常量算出来的，不是拍脑袋估的：

- **骑行** —— 1228.8 m 的环线跑三圈（五座碎片驿站布在一圈内，所以跑一圈就能全经过）。
  按 15 m/s 极速折算是约 4 分钟纯蹬车时间；真人花的时间要多得多。
- **打卡** —— 15 次。每次有固定的 1.0 秒镜头移动 + 1.5 秒停留 + 0.4 秒收尾
  = 约 **3 秒** 的过场，然后才进小游戏。
- **小游戏** —— 15 局，从 3 秒（茶）到约 9 秒（竹），还不算你自己的反应时间。
- **故事** —— 5 段首访对白 + 3 场郑铎戏。

骑一圈把五块碎片各收一次大约 **8–10 分钟**，游戏允许你就在这里停下
（走暂停面板那条路）。

## 技术

- **引擎**：Godot 4.6.2，Forward+
- **导出目标**：Web（主）、Windows 桌面、Android / 触屏
- **零贴图资产** —— 路面、地形、草皮全是程序化着色器，这也是 Web 导出能压小的原因
- **路网几何**：代码里解析采样的 8 字 lemniscate；不使用任何外部地图、GPS 轨迹或真实道路数据
- **植被**：`MultiMesh` 实例化散布，按同心环流式加载，逐格确定性放置
- **驿站**：手工 GLB 地标，运行时染色
- **音频**：程序化合成的环境声与小游戏音效（无采样文件）；BGM / SFX 分开静音
- **语言**：中英双语界面，可切换
- **字体**：开源 LXGW WenKai，按实际用到的字符做了子集化
- **存档**：每次打卡后自动本地保存

## 怎么验的

这个项目有 **34 条回归（27 条无头 + 7 条要开窗口）+ 8 套出图定妆照 + 2 条探针**，
一条命令全跑完：

```bash
bash tools/check_all.sh
```

```
=== headless 回归 ===
  verify_8_shape               PASS             1s    7 ok / 0 fail
  verify_water                 PASS             3s   23 ok / 0 fail
  ...
=== 自检摘要 ===
  跑过 27 条：PASS 27 / FAIL 0 / 没跑成 0
  断言 1396 条，其中 0 条红
  没跑（要开窗口，--headless 跑出来的 PASS 是假的）：7 条
```

四种判定，各有各的理由：

| 判定 | 意思 |
|---|---|
| `PASS` | 打了断言，且没有 `[FAIL]` |
| `FAIL` | 打了 `[FAIL]`，或退出码非 0 |
| `TIMEOUT` / `NO-ASSERT` | **一条断言都没打出来** —— 没跑成，不许算通过 |

最后一栏是这套东西存在的理由：一条回归自己抛异常时，`--quit-after` 收掉进程的
退出码是 **0**，一行断言都没打过的回归看着像跑通了。所以判据不信退出码，
只信「有没有 `[FAIL]`」加「有没有打出断言」两件事。

**7 条要开窗口**（`bash tools/check_all.sh --window`）：`verify_panel_keyboard`、
`verify_checkin_all5`、`verify_mini_game_keys`、`verify_bamboo_done`、
`verify_bamboo_world`、`verify_demo_path`、`verify_camera_bike`。
它们量的是**真焦点路由**和**真 16:9 视口**
——`--headless` 用的是 dummy display server，不做焦点路由，键盘事件到不了
`_gui_input`，跑出来的 PASS 是假的。它们不在默认轮次里，是因为没跑的条目必须
在输出里明写「没跑」并给出跑法，不能靠沉默冒充。

**8 套出图**（`bash tools/check_all.sh --lookdev`）存到 `user://`，断言全是**像素**的。
这一族同样不能加 `--headless`：dummy renderer 不编译着色器、`_draw()` 一笔都不落盘。
有些缺陷只有看图才能发现，而尺寸断言当时全绿 —— 比如草皮一度被调成一片 0.34×0.15m
的卡片，回归说「位置正确、数量正确」，图上是一地龙舌兰。

### 几条关键不变量

| 量 | 值 | 守着它的是什么 |
|---|---|---|
| 环路总长 | 1228.8m（±2.0） | `verify_8_shape` |
| 中心线点数 | 961 | `verify_8_shape` |
| 8 字被中线穿过 | 4 次（两个环各进出一次） | `verify_8_shape` |
| 驿站 | 16 座，名字/模型/碎片顺序全对得上 | `verify_stations` |
| 中英文案 key 集合 | 逐字相同 | `verify_story` |
| 路面高度取的是上层 | 路外返回 `-INF` 而非 0 | `verify_road_height` |
| 每株植物贴地 | 偏差 < 0.05m | `verify_vegetation` |
| 水的岸线高出路面 | ≥ 0.35m（三处 0.67 / 0.40 / 0.40） | `verify_water` |
| 碎片颜色两处副本 | `Postcard` 与 `FragmentBar` 逐值相同 | `verify_postcard_ending` |
| 顶栏标签位置 | 入账时横坐标一个像素都不许动 | `verify_mood_mask` |

### 工程上真正值钱的那部分不是回归数量

是 `CLAUDE.md` 末尾那份**陷阱清单** —— 近百条「这个项目里踩过、而且症状不像 bug 的坑」，
每条都写着成因和判据。举三个例子：

- **`Transform3D.scaled()` 会把 origin 一起缩放**。它不是「只缩 basis」。
  植被实例曾因此让每株植物落在「地面高度 × 缩放」上，灌木平均浮空 0.74m、树 7.79m、
  最多 102m —— 表现是大片灌木悬在半空，没有任何异常抛出。
- **`ALPHA_SCISSOR_THRESHOLD` 判的是 `ALPHA`，而 `ALPHA` 默认是 1.0**。
  只设阈值不写 `ALPHA`，scissor 什么都不剔，整张卡片全不透明 —— 草皮渲成一地绿色多边形。
  这坑是看截图发现的：headless 下不编译着色器，回归全绿也照样错。
- **一条回归在绿，可能是因为它自己踩在它要守的那个漏洞上**。
  判断一条回归可不可信，要问的不是「它断言了什么」，而是「它凭什么能通过」：
  修好被测的漏洞时如果它变红，先怀疑它当初是踩着漏洞在跑。

每加一条新断言，都要先证明它会红 —— 故意弄坏、看它红、撤掉。第一版
`verify_8_shape` 手抄了一份 `road_data.gd` 的路点表，拿自己抄的这份和原始数据比，
产品一次都没被加载过：把 `road_data.gd` 整个改写成一条直线，它照样全绿。

## 老实说：这一版做到了什么

**已实现**：完整环线、三次到访进度、15 局轮换小游戏、明信片正反两面 PNG 导出、
环境声与音效、本地存档、语言切换、移动端摇杆、移动端打卡、第二圈才切换的昼夜、
Web 与 Windows 导出预设。

**这一版没有**：原计划的路边彩蛋、分站点的音乐变奏、成体系的美术设定板。
反派存在，但只有一条弧线，没有分支。
