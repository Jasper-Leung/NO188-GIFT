### P0-1 的详细复评：三个成因假设，我逐个做了对照实验

第四轮把成因判给「反照率低」，改法是 `0.168 → 0.355`（线性 0.023 → 0.105）。
这个改动**真实生效**了：路面不再是一块接近纯黑的表面，黄昏也不再直接黑掉。
但渲出来仍然是蓝紫色——2× 放大后读成**靛蓝迷彩布**。

算一下就知道它为什么还是蓝的：

```
albedo 线性      = (0.105, 0.100, 0.095)   ← 暖中性，改对了
渲出来线性       = (0.117, 0.110, 0.207)   ← 正午中段
逐通道照度比     = (1.11,  1.10,  2.18)    ← 蓝的那一路是红的两倍
```

**照度是蓝的。** 而正午的天空实测 `b/r ≈ 2.2~3.5`——完全对得上。
路面是全场唯一一块大面积、近水平、朝天的中性面，
它把整个蓝色天穹原样接了过来，而**没有任何一份暖的地面反弹去抵消**。

于是我做了三个对照实验，每一个都是改一行、重拍同一套图、量同一片区域的中位数：

| 假设 | 做法 | 正午 `b−r` | 04b `b−r` | 结论 |
| :--- | :--- | :-: | :-: | :--- |
| 基线 | — | +28 | +37 | — |
| ① 蓝自发光 | `EMISSION = vec3(0)` | +29 | +37 | **证伪** |
| ② 天光环境光 | `ambient_light_sky_contribution 1.0→0.62` + `ambient_light_color` 转暖 | +28 | +37 | **证伪** |
| ③ 掠射菲涅尔反射 | `SPECULAR = 0.0` | +25 | +35 | **证伪**（压暗了 13 个单位，蓝只掉 3 个） |

关于②我多做了一步：用一次性探针确认那个值**确实被读到了**
（`ambient_light_sky_contribution = 0.62`、`ambient_light_color = (0.68,0.64,0.57)`），
而渲染逐像素不变。**所以这条路是旋钮本身在 `ambient_light_source = 3` 下对漫反射无效**，
不是「改了没生效」。这一条能省下下一个人一次完整的重拍。

> **如实记：成因收窄到「天穹漫反射辐照度」，但我没有把它彻底钉死，不猜。**
> 下一个该做的实验只有一步：把片元里的 `ALBEDO` 临时写成固定的 `vec3(0.35)`
> 重拍一张——渲出来仍然是蓝的，成因就确认在漫反射而不在材质，
> 剩下的旋钮只剩 `DAY_SKY_TOP`（把 0.95 那个蓝通道收下来）或者给路面单独补一份暖的半球项。

## 4. 问题清单

### P0 — 挡在「能给人看」前面的

#### P0-1　全屏最大的一块表面仍然是蓝紫色的

**现象**：`04b_villain` 近景路面 `b−r = +37`、正午中段 `+28`、黄昏 `+6`，
中位饱和度 0.24。2× 放大后读成靛蓝迷彩布。

**为什么这一轮没修好**：第四轮把成因判给了 albedo，albedo 确实改了，
但 albedo 是暖中性的、照明是蓝的——**改错了那一半**。
三个对照实验见 §2，结论是**成因在漫反射天光，不在材质**。

**判据现状**：`verify_asphalt_shader.gd` 守的全是**读源码文本**那一族
（uniform 有没有被读、边线宽度、`plaza_mode`、默认值 == `RoadBuilder` 的常量表）。
它守「边线画没画出来」，守不到「路面是什么颜色」。

**建议改法**（先做那一步实验，再谈调参）

1. 把 `ALBEDO` 临时写成 `vec3(0.35)` 重拍一张——**确认成因在漫反射**。
2. 若确认，旋钮只剩两个：
   - 收 `DAY_SKY_TOP` 的蓝（`(0.27,0.53,0.95)` 的 b 是 r 的 3.5 倍，
     这是一个对美术很不友好的天空），或者
   - 给路面材质补一份**暖的半球环境项**（绕开那个在 `ambient_light_source=3`
     下失效的旋钮）。
3. **新增像素判据**（带正对照）：
   - 「正午路面中位 `|b−r| ≤ 12`」
   - 「正午路面中位饱和度 `≤ 0.12`」
   - 正对照 = 同一帧里**草地**的 `|b−r|`：它现在是 −73（明显偏绿），
     证明这把尺子量得出色偏；没有这条，把路面调成纯灰也照样绿。

#### P0-2　黄昏的天顶仍是一条 63px 高的饱和红带，交界是 2 像素硬边

**量到的**（`12c_dusk`，x=300 竖切）：

```
y=  0..42   ( 23, 20, 29)   深蓝紫      ← DUSK_SKY_TOP 那一档，出来了
y= 48..132  (177, 78, 48)   饱和红带    ← 63px 高，g/r≈0.37~0.46，b/r≈0.20~0.26
y=133       (180,106, 87)
y=134       (187,154,162)   淡粉        ← 一行之内绿 +76、蓝 +114
```

正午那张在**同一条 y** 上有同一条缝：
`y=130 (118,151,218)` → `y=140 (209,215,224)`，**绿 +91、蓝 +64**。

**成因**：那是 `ProceduralSkyMaterial` 的**天穹地平线**——
sky 半球和 ground 半球在视线水平方向上是两半，`ground_horizon_color`
（`DAY_GND_HORIZON = (0.62,0.70,0.60)`）和 `sky_horizon_color`
（`(0.72,0.85,0.97)`）本来就是两个颜色，接缝是**结构性的**，
而 `sky_curve = 0.15` 让天空那一侧在接近地平线时还没走到 `sky_horizon_color`，
于是缝的上侧是**饱和的天顶色**、下侧是**接近地平线的淡霾**，反差拉满。

**判据现状**：`lookdev_journey.gd` 的 `SKY_ROWS = [0.10, 0.14, 0.18, 0.22]`
四条**全部落在缝的上侧**，缝以下整个区域**没有任何一条断言**。
更关键的是，`dusk_gr >= 0.10 and dusk_br >= 0.10` 这一条量到的是 **0.378 / 0.250**——
门槛松了 3.8 倍，而那条 63px 的红带就是被它放过去的。

**建议改法**

- 判据：**「天带内相邻两行的最大通道跳变 ≤ 24」**——这是「有没有硬边」的正确量，
  而现在量的是「天色对不对」。正对照 = 地形轮廓那一行的跳变量级。
- 取样带下移跨过缝（加 `fy 0.21 / 0.24`）。
- 收紧 `dusk_gr / dusk_br` 门槛：0.10 → 0.45（现在实测 0.378，会红，这是对的）。
- 常量侧：让 `*_GND_HORIZON` 向 `*_SKY_HORIZON` 靠，
  并把 `sky_curve` 调大到接近地平线时天色已经收敛。

#### P0-3　竹在玩家真正盯着的那一格里读成窗格（第四轮判它「✓」是错的）

第四轮的表格里写着「竹 | 三根带节的竹子 ✓」。
我当时看的是**明信片上的大尺寸**——那一版有叶子，确实是竹丛。
**而玩家一路盯着的是底栏那个 22px 的盘**：叶子在那个尺寸上不存在了，
`FragmentBar._draw_bamboo` 剩下的是 **3 根竖线 × 每根 4 道横节 = 一张窗格**。

同一件东西在两个尺寸上读成两样东西，这是这一族问题的第四份。

**建议改法**

- **小尺寸换算法**：大尺寸保留竹丛（带叶），22px 那档换成
  「三根收分的竹身 + 两片叶」的剪影——量「三根竖条的**收分**」而不是量「有几道节」。
- 补 `verify_mini_game.gd` 6k 节的缺口：现在那节量的是云/茶/琴，
  **没有一条量竹在小尺寸下的可辨识性**。
- 顺带把竹收进 `FragmentIcon`（见 P2-1）。

### P1 — 会被评委当场指出来的

#### P1-1　黄昏草皮的饱和度不但没降，反而比白昼更高

| | 中位 sRGB | 中位饱和度 | p95 线性亮度 |
| :--- | :--- | :-: | :-: |
| 正午草带 | (159,166,86) / (94,133,73) | 0.474 / 0.450 | 0.554 / 0.354 |
| **黄昏草带** | **(81,55,15)** / (25,32,17) | **0.796 / 0.514** | 0.083 / 0.041 |

第四轮 P1-1 的改法是把 `DUSK_SUN_COL` 从 `(1.0,0.70,0.42)` 降纯度到
`(1.0,0.80,0.64)`。**方向对，但旋钮不是那个。**
渲出来的饱和度由**草皮自身 albedo 的蓝通道**决定
（`blade_base` b=0.270 / `ground_color` b=0.285），
太阳色降纯度几乎不动那个乘积——绿被抬上去了一点，蓝还是那么低。

**判据现状**：`verify_day_cycle.gd` 这一轮新增的三条**全部在量常量的纯度**
（`min/max(DUSK_SKY_HORIZON) >= 0.50`、`min/max(DUSK_SUN_COL) >= 0.50`、
再加一条「收着写之后仍然是暖的」当正对照）。
**没有一条量渲出来的像素。**

> 这是这个项目自己写过的那条教训，第四轮 §7 原话：
> 「当一个项目把『我不测观感』写进自己的文档时，要把它读成『观感由看图负责』。」
> 第五条判据写得很用心，但它量的是**我写下的那个数**，不是**玩家眼睛看到的那张图**。

**建议改法**

- 判据改成量像素：「黄昏草带中位饱和度 `≤ 0.55`」+
  正对照「正午草带 `≤ 0.50`」（现在实测 0.474 / 0.796）。
- 旋钮：抬 `blade_*` / `ground_*` 的蓝通道，或者把 `DUSK_FILL_ENERGY`（0.55）提上来——
  冷补光正是用来给暗面一点和太阳相反的色，它现在太弱了。
